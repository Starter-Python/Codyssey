## 📌 프로젝트 1: Make vs Zapier 동일 워크플로우 비교

### 1. 개요
동일한 자동화 워크플로우를 Make와 Zapier로 각각 구현하고, 두 플랫폼을 비교 분석한 프로젝트입니다.

### 2. 워크플로우 시나리오
```
Google Form 퀴즈 제출 (10문제)
        │
        ▼
   점수 채점 (8문제 이상 = 합격)
        │
   ┌────┴────┐
   ▼         ▼
 [합격]    [불합격]
   │         │
   ▼         ▼
Google Sheets 기록 + Discord 알림 (각 경로별 메시지 분기)
```

### 3. 구현 방식 차이

| 구분 | Make | Zapier |
|------|------|--------|
| 분기 처리 | **Router** 모듈로 합격/불합격 경로 분기 | **Filter** 기반으로 Zap 2개 분리 |
| 시나리오 구조 | 1개 시나리오에서 전체 처리 | 합격용 Zap + 불합격용 Zap |
| 시각화 | 플로우차트 형태로 직관적 | 리스트(순차) 형태 |

### 4. 비교 분석 요약

| 항목 | Make | Zapier |
|------|------|--------|
| UI/UX | 시각적 플로우, 학습 곡선 있음 | 직관적, 초보자 친화적 |
| 난이도 | 중 (Router, 매핑 개념 필요) | 하 (단계별 안내) |
| 연동 범위 | 세밀한 API 제어 가능 | 앱 연동 수가 압도적으로 많음 |
| 무료 플랜 | 월 1,000 오퍼레이션 | 월 100 태스크 (제한적) |
| 로그 확인 | 실행 내역 상세 확인 용이 | Zap History로 확인 가능 |

### 5. 결론
- **복잡한 분기/다단계 로직** → Make 우세
- **빠른 구축, 다양한 앱 연동** → Zapier 우세
- 무료 플랜 기준 가성비는 Make가 유리

## 🎾 프로젝트 2: 스쿼시 ESL 리그 선수 관리 AI 에이전트

### 1. 개요
스쿼시 ESL 리그의 선수 정보와 경기 기록을 Google Sheets DB로 관리하고,
AI 에이전트가 자연어 질의를 받아 데이터를 조회·분석·업데이트하는 시스템입니다.

### 2. 시스템 아키텍처
```
사용자 (자연어 질의)
        │
        ▼
  AI 에이전트 (LLM)
   ├─ 의도 분석 (조회 / 기록 / 분석)
   ├─ Google Sheets 도구 호출
   └─ 응답 생성
        │
        ▼
  Google Sheets DB
   ├─ 시트1: 선수 프로필 (이름, 레벨, 연락처, 가입일)
   ├─ 시트2: 경기 기록 (날짜, 대진, 스코어, 승패)
   └─ 시트3: 리그 순위 (승점, 승률, 랭킹)
```

### 3. 주요 기능
1. **선수 조회**: "김OO 선수 전적 알려줘" → 프로필 + 최근 경기 요약
2. **경기 기록 입력**: "오늘 A vs B, 3:1로 A 승리" → 경기 기록 시트 자동 추가
3. **순위 분석**: "이번 달 승률 top 3는?" → 순위 시트 집계 후 응답
4. **알림 자동화**: 경기 결과 입력 시 Discord로 리그 알림 발송

### 4. 사용 기술
- **DB**: Google Sheets (3개 시트 구조)
- **자동화**: Make (Webhook → Sheets → Discord)
- **AI**: LLM 기반 에이전트 (자연어 → 도구 호출)

### 5. 기대 효과
- 수기 관리 대비 기록 누락/오류 감소
- 자연어로 누구나 데이터 조회 가능 (운영자 부담 감소)
- 리그 참여자 대상 실시간 순위/결과 공유

# 스쿼시 ESL 리그 선수 관리 AI Agent 시스템 레포트

## 0. 프로젝트 개요

본 프로젝트는 **스쿼시 ESL 리그 운영을 효율화하기 위한 선수 관리 AI Agent 시스템**을 기획한 것이다.  
리그 운영 과정에서 발생하는 선수 정보 관리, 경기 결과 기록, 순위 계산, 경기 피드백 작성 등의 반복 업무를 줄이고, 선수에게는 데이터 기반 피드백을 제공하는 것을 목표로 한다.

초기 MVP는 복잡한 서버나 데이터베이스 대신 **Google Sheets를 중심 데이터베이스처럼 사용**하고, **Make 또는 Zapier**를 통해 자동화 흐름을 구성하는 방식으로 설계하였다.  
AI Agent는 경기 결과와 선수 스탯을 바탕으로 선수별 피드백을 생성하는 역할을 담당한다.

---

## 1. 문제 및 배경상황 설명

스쿼시 ESL 리그를 운영할 때 관리해야 하는 정보는 생각보다 많다.  
예를 들어 선수 명단, 선수별 실력 정보, 경기 일정, 세트별 점수, 승패 결과, 순위표, 경기 후 피드백 등을 계속 기록하고 업데이트해야 한다.

기존 방식에서는 이러한 작업을 운영자가 직접 수동으로 처리해야 한다.  
이로 인해 다음과 같은 문제가 발생할 수 있다.

### 1-1. 수동 관리의 어려움

| 문제 | 설명 |
|---|---|
| 경기 결과 정리 부담 | 경기 후 세트별 점수와 승패를 직접 기록해야 함 |
| 순위 계산 오류 가능성 | 승수, 세트 득실, 점수 득실 등을 수동 계산하면 실수 가능성이 있음 |
| 피드백 작성 시간 부족 | 모든 선수에게 경기별 피드백을 작성하기 어려움 |
| 데이터 분산 | 선수 정보, 경기 결과, 피드백이 여러 곳에 흩어질 수 있음 |
| 운영자 업무 증가 | 리그 규모가 커질수록 반복 업무가 많아짐 |

특히 순위 계산처럼 규칙이 명확한 작업은 사람이 직접 계산할 경우 실수가 생길 수 있다.  
또한 경기 피드백은 선수 성장에 도움이 되지만, 매 경기마다 운영자가 직접 작성하기에는 시간이 많이 필요하다.

따라서 리그 운영에는 다음과 같은 시스템이 필요하다고 판단했다.

- 선수 정보를 한 곳에서 관리할 수 있는 구조
- 경기 결과 입력 후 자동으로 순위가 계산되는 기능
- 경기 데이터를 기반으로 피드백을 생성하는 AI Agent
- 운영자에게 필요한 알림을 자동으로 보내는 자동화 흐름

---

## 2. AI를 활용하여 해결하게 된 이유

이 프로젝트에서 모든 기능을 AI로 처리하는 것은 적절하지 않다.  
예를 들어 승자 판정, 순위 계산, 점수 유효성 검사는 정답이 명확한 영역이므로 AI보다 알고리즘으로 처리하는 것이 더 안정적이다.

반면 경기 피드백 작성이나 선수 프로필 요약은 단순 계산만으로 해결하기 어렵다.  
세트별 점수 흐름, 선수 스탯, 최근 경기 결과를 종합해서 자연어로 설명해야 하기 때문이다.  
이 부분에서 AI Agent를 활용하면 운영자의 반복적인 글쓰기 부담을 줄이고, 선수에게 더 빠르게 피드백을 제공할 수 있다.

### 2-1. 알고리즘과 AI Agent의 역할 구분

| 작업 | 처리 방식 | 이유 |
|---|---|---|
| 세트 승자 판정 | 알고리즘 | 점수 기준이 명확함 |
| 경기 승자 판정 | 알고리즘 | 획득 세트 수로 결정 가능 |
| 순위표 계산 | 알고리즘 | 동일한 입력에는 동일한 결과가 필요함 |
| 선수 프로필 요약 | AI Agent | 숫자 데이터를 자연어로 해석해야 함 |
| 경기 피드백 작성 | AI Agent | 경기 흐름과 개선점을 문장으로 설명해야 함 |
| 개선 포인트 추천 | AI Agent | 최근 기록과 스탯을 종합해야 함 |
| 최종 검토 | 운영자 | AI 결과의 정확성과 표현을 확인해야 함 |

즉, 이 프로젝트의 핵심 방향은 **정답이 있는 계산은 알고리즘이 처리하고, 해석과 문장 생성은 AI Agent가 담당하는 구조**이다.  
이렇게 역할을 나누면 시스템의 안정성과 실용성을 동시에 높일 수 있다.

## 3. 해결 과정

## 3-1. 전체 시스템 구조 설계

초기 MVP는 다음과 같은 구조로 설계하였다.

```text
웹사이트 또는 입력 폼
  ↓
Google Sheets에 선수/경기 데이터 저장
  ↓
알고리즘으로 승자 및 순위 계산
  ↓
AI Agent가 경기 피드백 생성
  ↓
운영자가 피드백 검토
  ↓
선수 페이지 또는 Discord로 결과 공유
```

이 구조를 선택한 이유는 구현 난이도를 낮추면서도 실제로 동작 가능한 형태를 만들기 쉽기 때문이다.  
Google Sheets는 데이터를 확인하고 수정하기 쉽고, Make/Zapier는 별도 서버 개발 없이 자동화 흐름을 구성할 수 있다.

---

## 3-2. 데이터 구조 설계

Google Sheets에는 다음과 같은 시트를 만든다.

| 시트명 | 역할 |
|---|---|
| Players | 선수 기본 정보 저장 |
| PlayerStats | 선수별 능력치 및 특성 저장 |
| Matches | 경기 기본 정보 저장 |
| MatchSets | 세트별 점수 저장 |
| Rankings | 순위표 계산 결과 저장 |
| FeedbackLogs | AI 피드백 기록 저장 |

### 주요 컬럼 예시

#### Players

```text
playerId, name, nickname, level, dominantHand, playStyle, joinedAt, status
```

#### Matches

```text
matchId, seasonId, playerAId, playerBId, winnerId, status, scheduledAt, completedAt
```

#### MatchSets

```text
setId, matchId, setNumber, playerAScore, playerBScore, setWinnerId
```

#### Rankings

```text
playerId, matchesPlayed, wins, losses, winRate, setsWon, setsLost, pointDiff, rank
```

#### FeedbackLogs

```text
feedbackId, matchId, playerId, summary, strengths, weaknesses, nextFocus, coachComment, reviewStatus
```

이처럼 데이터를 분리하면 경기 결과, 순위, 피드백을 체계적으로 관리할 수 있다.

---

## 3-3. 경기 결과 처리 방식

경기 결과는 세트별 점수를 입력하면 자동으로 승자를 판단하도록 설계한다.  
예를 들어 3판 2선승제라면 먼저 2세트를 가져간 선수가 승자가 된다.

점수 입력 시에는 다음과 같은 검증이 필요하다.

| 검증 항목 | 설명 |
|---|---|
| 빈 점수 확인 | 점수가 입력되지 않으면 저장 불가 |
| 음수 점수 방지 | 0보다 작은 점수는 허용하지 않음 |
| 세트 종료 조건 확인 | 일반적으로 11점 이상이어야 세트 종료 |
| 2점 차 규칙 확인 | 듀스 상황에서는 2점 차가 필요 |
| 승자 결정 여부 확인 | 승자가 결정되지 않으면 경기 완료 처리 불가 |

이 과정은 AI가 아니라 알고리즘으로 처리한다.  
왜냐하면 경기 규칙은 명확하며, 항상 같은 결과가 나와야 하기 때문이다.

---

## 3-4. 순위 계산 방식

순위표는 경기 결과를 바탕으로 자동 계산한다.  
기본 정렬 기준은 다음과 같이 설정할 수 있다.

```text
1순위: 승수
2순위: 세트 득실
3순위: 점수 득실
4순위: 승률
```

예를 들어 어떤 선수가 3승 1패이고 세트 득실이 +4라면, 이 정보가 Rankings 시트에 자동 반영된다.  
이를 통해 운영자가 직접 순위를 계산하지 않아도 항상 최신 순위표를 유지할 수 있다.

---

## 3-5. AI Agent 피드백 생성

AI Agent는 경기 결과와 선수 스탯을 입력받아 선수별 피드백을 생성한다.  
출력은 운영자가 검토하기 쉽도록 JSON 형태로 제한한다.

### AI Agent 입력 예시

```json
{
  "player": {
    "name": "Player A",
    "level": "Intermediate",
    "stats": {
      "serve": 75,
      "stamina": 68,
      "consistency": 60
    }
  },
  "match": {
    "result": "win",
    "sets": [[11, 8], [9, 11], [11, 6]]
  }
}
```

### AI Agent 출력 예시

```json
{
  "summary": "초반과 후반의 집중력이 좋았고, 마지막 세트에서 안정적으로 경기를 마무리했습니다.",
  "strengths": [
    "중요한 순간에 득점 흐름을 가져왔습니다.",
    "마지막 세트에서 실수를 줄였습니다.",
    "상대보다 경기 운영이 안정적이었습니다."
  ],
  "weaknesses": [
    "두 번째 세트에서 흐름을 내준 부분은 보완이 필요합니다.",
    "연속 실점 상황에서 대응 전략이 필요합니다.",
    "서브 이후 랠리 연결의 안정성을 높일 필요가 있습니다."
  ],
  "nextFocus": [
    "중반 집중력 유지",
    "서브 후 첫 번째 샷 안정화",
    "연속 실점 시 템포 조절"
  ],
  "coachComment": "좋은 경기였습니다. 다음에는 중간 세트의 흔들림을 줄이는 데 집중하면 더 성장할 수 있습니다."
}
```

AI가 생성한 피드백은 바로 선수에게 공개하지 않고, 운영자가 검토한 후 공개하는 방식으로 설계하였다.  
이를 통해 AI의 부정확한 표현이나 과도한 해석을 줄일 수 있다.

---

## 3-6. 자동화 도구 활용

Make 또는 Zapier를 사용하면 경기 결과 입력 이후의 반복 작업을 자동화할 수 있다.

### 자동화 시나리오 예시

```text
Google Sheets에 경기 결과 추가
  ↓
Make가 새 행 감지
  ↓
관련 선수 정보와 경기 기록 조회
  ↓
AI Agent에 피드백 생성 요청
  ↓
AI 응답을 FeedbackLogs 시트에 저장
  ↓
Discord 운영자 채널에 검토 알림 전송
```

이 자동화를 통해 운영자는 매번 데이터를 복사하거나 알림을 직접 보낼 필요가 없다.  
경기 결과만 입력하면 이후 과정이 자동으로 이어진다.

## 4. 결과

본 프로젝트를 통해 스쿼시 ESL 리그 운영을 위한 AI Agent 기반 시스템 구조를 설계할 수 있었다.  
아직 완성된 서비스라기보다는 MVP 기획 단계이지만, 실제 구현 가능한 수준으로 데이터 구조와 자동화 흐름을 정리하였다.

### 4-1. 기대되는 결과

| 대상 | 기대 효과 |
|---|---|
| 운영자 | 경기 결과 정리, 순위 계산, 피드백 작성 부담 감소 |
| 선수 | 경기별 피드백을 통해 강점과 약점 파악 가능 |
| 리그 전체 | 데이터 기반으로 더 체계적인 운영 가능 |
| 학습 측면 | 노코드 자동화, AI Agent 설계, 데이터 구조 설계 경험 |

특히 이번 프로젝트에서는 AI를 무조건 모든 곳에 사용하는 것이 아니라, **AI가 잘할 수 있는 영역과 알고리즘이 더 적합한 영역을 구분한 점**이 중요하다.

- 알고리즘: 승자 판정, 순위 계산, 점수 검증
- AI Agent: 경기 요약, 강점/약점 분석, 다음 경기 개선 포인트 추천
- 운영자: 최종 검토 및 공개 여부 결정

이 구조는 안정성과 활용성을 모두 고려한 방식이라고 볼 수 있다.

---

## 4-2. 한계점

초기 MVP는 Google Sheets 기반이므로 다음과 같은 한계가 있다.

| 한계 | 설명 |
|---|---|
| 데이터 규모 제한 | 참가자와 경기 수가 많아지면 관리가 느려질 수 있음 |
| 권한 관리 제한 | 선수별 로그인이나 세밀한 접근 제어가 어려움 |
| AI 피드백 정확도 한계 | 실제 경기 영상이 아닌 입력 데이터만 기반으로 분석함 |
| 운영자 검토 필요 | AI 결과를 그대로 공개하기에는 위험할 수 있음 |

따라서 실제 서비스로 확장하려면 Supabase, Firebase, PostgreSQL 같은 데이터베이스와 사용자 인증 기능을 추가하는 것이 좋다.

## 4-3. 향후 개선 방향

향후에는 다음 기능을 추가할 수 있다.

```text
1. 선수별 로그인 기능
2. 시즌별 통계 비교
3. 경기 영상 업로드 및 AI 분석
4. 모바일 화면 최적화
5. QR 코드 기반 경기 결과 입력
6. 자동 대진표 시각화
7. 선수별 성장 그래프 제공
8. 상대 전적 기반 경기 예측
```

## 5. 결론

본 프로젝트는 스쿼시 ESL 리그의 반복적인 운영 업무를 줄이고, 선수에게 데이터 기반 피드백을 제공하기 위한 AI Agent 시스템이다.

핵심은 다음과 같다.

```text
경기 결과 입력
  ↓
순위 자동 계산
  ↓
AI Agent 피드백 생성
  ↓
운영자 검토
  ↓
선수에게 공유
```

이를 통해 운영자는 리그 관리 시간을 줄일 수 있고, 선수는 자신의 경기 내용을 더 구체적으로 이해할 수 있다.  
또한 프로젝트를 진행하면서 Google Sheets 기반 데이터 설계, Make/Zapier 자동화, AI Agent 프롬프트 설계, 알고리즘과 AI의 역할 분리 방법을 학습할 수 있었다.

결론적으로 이 프로젝트는 단순한 리그 관리 도구가 아니라, **노코드 자동화와 AI Agent를 결합한 실용적인 학습 프로젝트**라고 할 수 있다.

# [프로젝트 2] 자유 주제 자동화 설계 및 구현

## 반도체 뉴스 자동 수집 · AI 요약 뉴스레터 발송

---

## 1. 반복 업무 정의

> **매일 아침 반도체 관련 뉴스를 직접 검색하고, 중요한 기사를 골라 스프레드시트에 정리한 뒤, 제목만 보고 대략적인 내용을 파악해 메일로 정리하는 작업**

- 사람이 수작업으로 하면 매일 아침 **15~20분** 소요
- 여러 언론사 뉴스를 일일이 확인 → 피로도 높고 누락 발생
- 기사 내용을 빠르게 파악하기 어려움 (제목만으로는 감이 안 옴)

→ 이 반복 업무를 **하루 1회 자동 실행되는 뉴스레터 파이프라인**으로 자동화한다.

| **선정 이유 2** | **무료 플랜 1,000 Operations/월** 범위 내에서 충분히 구현 가능 |

## 3. 워크플로우 설계

본 자동화는 **2개의 시나리오**로 구성된다. (수집 / 발송 분리)

### 3-1. 시나리오 A — 뉴스 수집 & 키워드 분류

```
[RSS] ──> [Router] ──┬──> [Google Sheets: Add a Row]  (1st 경로: 메모리 반도체)
Watch feed items     │
(Trigger)            └──> [Google Sheets: Add a Row]  (2nd 경로: 그 외 분류)
```

| 단계 | 모듈 | 역할 |
|------|------|------|
| **Trigger** | RSS – Watch RSS feed items | 반도체 뉴스 RSS 피드에서 새 기사 감지 |
| **조건 분기** | Router | 기사 키워드에 따라 분류 경로 분기 |
| **Action 1** | Google Sheets – Add a Row (1st) | 메모리 반도체 관련 기사 저장 |
| **Action 2** | Google Sheets – Add a Row (2nd) | 그 외 기사 저장 |

### 3-2. 시나리오 B — AI 요약 & 메일 발송

```
[Google Sheets] ──> [Gemini AI] ──> [Text Aggregator] ──> [Gmail]
Search Rows          Simple prompt    (여러 기사 → 1통)     Send an email
(Trigger: 매일 10AM)  AI 예상내용 생성                        HTML 뉴스레터 발송
```

| 단계 | 모듈 | 역할 |
|------|------|------|
| **Trigger** | Google Sheets – Search Rows | 매일 10:00 저장된 기사 조회 (스케줄 실행) |
| **Action 1** | Google Gemini AI – Simple text prompt | 제목 기반 예상 내용 + 주목할 점 자동 생성 |
| **Action 2** | Tools – Text Aggregator | 여러 기사를 메일 1통으로 합침 |
| **Action 3** | Gmail – Send an email | HTML 형식 뉴스레터 발송 |

## 4. 요구사항 충족 체크

| 공통 요구사항 | 충족 여부 | 구현 내용 |
|--------------|:--------:|-----------|
| Trigger 1개 이상 | ✅ | RSS Watch feed / Sheets Search Rows |
| Action 2개 이상 | ✅ | Sheets 저장 · Gemini 요약 · Aggregator · Gmail 발송 (4개) |
| 조건 분기(Router) 1개 이상 | ✅ | Router로 키워드별 2개 경로 분기 |
| 각 분기 경로 1회 이상 실행 확인 | ✅ | 스프레드시트에 분류된 기사 2건 저장 확인 (실행 결과 참조) |
| Trigger 발생 시 자동 실행 | ✅ | 매일 지정 시각(오전) 자동 스케줄 실행 설정 |

## 7. 보너스 1 — AI 연동 Action

- **Google Gemini AI (Gemini 2.5 Flash)** 모듈을 Action으로 추가
- 기사 **제목**을 입력받아 다음을 자동 생성:
  1. **제목 기반 예상 내용** (3~4줄) — 기사가 다룰 내용을 추론
  2. **주목할 점** (2줄) — 업계·투자 관점의 시사점
- 프롬프트에 `<br>` 태그 규칙을 명시하여 **HTML 메일에서 줄바꿈이 깔끔하게 렌더링**되도록 최적화

## 9. 배운 점 · 트러블슈팅

| 문제 | 원인 | 해결 |
|------|------|------|
| 메일 본문이 한 줄로 뭉침 | HTML 모드에서 줄바꿈(`\n`) 무시 | 프롬프트에 `<br>` 태그 명시 |
| `<b>` 태그가 글자로 보임 | 내용이 제목(Subject) 칸에 들어감 | 본문(Content) 칸으로 이동 + Body type = Raw HTML |
| 메일이 중간에 잘림 | 제목 칸 길이 제한 | 본문 칸으로 이동하여 해결 |
| 링크가 "정보 없음" | Sheets 링크 필드 매핑 확인 | C열 링크 정상 매핑 확인 |

> **핵심 인사이트**: 생성형 AI의 출력 형식(줄바꿈, 태그)까지 프롬프트로 통제해야 최종 결과물의 품질이 완성된다.

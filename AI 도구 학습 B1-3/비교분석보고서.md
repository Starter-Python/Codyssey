## 1. 프로젝트 개요

### 사용 도구
| 구분 | 도구 |
|------|------|
| 자동화 도구 1 | **Make** (구 Integromat) |
| 자동화 도구 2 | **Zapier** |

### 구현한 워크플로우
> **상식 퀴즈 자동 채점 및 알림 시스템**

Google Form으로 상식 퀴즈(10문항)를 응시하면,  
점수에 따라 자동으로 합격/불합격을 분류하고  
Google Sheets에 기록 + Discord로 관리자에게 알림을 전송하는 자동화 시스템

### 합격 기준
- **8점 이상** → 합격 처리
- **7점 이하** → 불합격 처리

## 2. 워크플로우 설계

### 공통 흐름도

```
[Trigger] Google Form 응답 제출
            ↓
[조건 분기] 점수 >= 8 ?
            ↓
    ┌───────┴───────┐
   YES              NO
    ↓               ↓
[Action 1]      [Action 1]
Sheets 합격 기록  Sheets 불합격 기록
    ↓               ↓
[Action 2]      [Action 2]
Discord 합격 알림  Discord 불합격 알림
```

### 포함된 요소
| 요소 | 내용 |
|------|------|
| **Trigger** | Google Forms - 새 응답 제출 시 |
| **조건 분기** | Make: Router / Zapier: Filter by Zapier |
| **Action 1** | Google Sheets - 응답 데이터 행 추가 |
| **Action 2** | Discord - Webhook으로 알림 메시지 전송 |

## 3. 구현 과정 요약

### Make 구현

**시나리오 구성**

Make는 하나의 시나리오(Scenario) 안에서 모든 분기를 처리한다.

```
Google Forms (Watch Responses)
    → Router
        → [1st 경로] Filter: 점수 < 8
              → Google Sheets (불합격 시트에 기록)
              → Discord (불합격 알림 전송)
        → [2nd 경로] Filter: 점수 >= 8
              → Google Sheets (합격 시트에 기록)
              → Discord (합격 알림 전송)
```

**구현 단계**
1. Google Forms 모듈 연결 (Watch Responses)
2. Router 모듈 추가 → 2개 경로 생성
3. 각 경로에 Filter 조건 설정 (점수 기준)
4. Google Sheets 모듈 연결 (Add a Row)
5. Discord Webhook URL로 Send a Message 모듈 연결
6. 시나리오 활성화 후 테스트 실행

**실행 결과 (캡처 이미지 참조)**
- 1st 경로 (불합격): 실행 횟수 0 → 조건 미충족 시 자동 스킵
- 2nd 경로 (합격): 실행 횟수 1 ✅ → Sheets 기록 + Discord 알림 전송 확인

---

### Zapier 구현

**Zap 구성**

Zapier는 조건 분기마다 별도의 Zap을 생성해야 한다.

```
[Zap 1 - 합격용]
Google Forms (New Form Response)
    → Filter by Zapier: 점수 >= 8
    → Google Sheets (Create Spreadsheet Row)
    → Discord (Send Channel Message: 합격 알림)

[Zap 2 - 불합격용]
Google Forms (New Form Response)
    → Filter by Zapier: 점수 < 8
    → Google Sheets (Create Spreadsheet Row)
    → Discord (Send Channel Message: 불합격 알림)
```

**구현 단계**
1. Zap 1 생성: Google Forms Trigger 설정
2. Filter by Zapier 추가 → 점수 >= 8 조건 설정
3. Google Sheets Action 연결
4. Discord Action 연결 (Webhook)
5. Zap 1 활성화
6. Zap 2 동일 구조로 생성 (조건만 반대로)
7. 양쪽 Zap 테스트 실행

**실행 결과 (캡처 이미지 참조)**
- Zap 1 (합격): Filter 통과 → Sheets 기록 + Discord 알림 ✅
- Zap 2 (불합격): Filter 통과 → Sheets 기록 + Discord 알림 ✅

## 4. 도구 비교 분석

### 비교표

| 비교 항목 | Make | Zapier |
|-----------|------|--------|
| **UI/UX** | 캔버스 기반 시각적 흐름도 | 단계별 리스트 형식 |
| **조건 분기 방식** | Router로 하나의 시나리오에서 다중 분기 처리 | Filter 사용, 분기마다 별도 Zap 생성 필요 |
| **설정 난이도** | 초기 학습 필요, 익숙해지면 직관적 | 단순 자동화는 쉬움, 복잡해질수록 관리 어려움 |
| **무료 플랜 실행 횟수** | 월 1,000회 | 월 100회 |
| **무료 플랜 폴링 주기** | 15분 간격 (지연 발생 가능) | 거의 실시간 (즉시 감지) |
| **연동 서비스 범위** | 1,000개 이상 앱 지원 | 6,000개 이상 앱 지원 |
| **실행 로그 확인** | 시나리오 히스토리에서 모듈별 상세 확인 가능 | Zap History에서 단계별 확인 가능 |
| **복잡한 로직 처리** | 하나의 시나리오로 복잡한 흐름 구성 가능 | 복잡할수록 Zap 수가 폭발적으로 증가 |
| **가격 대비 성능** | 무료 플랜에서 강력한 기능 제공 | 무료 플랜 제한이 많음 (100회/월) |
| **데이터 가공** | 내장 함수, 수식, 반복 처리 등 고급 기능 지원 | 기본적인 데이터 변환만 지원 |

## 5. 각 도구의 장단점

### Make

**장점**
- 하나의 시나리오에서 Router로 다중 분기를 한눈에 관리
- 무료 플랜 월 1,000회로 실용적인 테스트 가능
- 시각적 캔버스로 전체 흐름 파악이 쉬움
- 내장 함수, 반복(Iterator), 집계(Aggregator) 등 고급 기능 제공

**단점**
- 무료 플랜 폴링 주기 15분 → 실시간 처리 불가
- 처음 접하면 UI가 낯설어 학습 시간 필요
- 일부 고급 모듈은 유료 플랜에서만 사용 가능

---

### Zapier

**장점**
- 단계별 리스트 UI로 초보자도 빠르게 설정 가능
- 6,000개 이상의 방대한 앱 연동 지원
- 실시간에 가까운 빠른 트리거 감지

**단점**
- 조건 분기마다 별도 Zap 생성 필요 → 관리 복잡도 증가
- 무료 플랜 월 100회 제한 → 실사용에 부족
- 복잡한 워크플로우 구성 시 한계가 명확함
- 데이터 가공 기능이 Make에 비해 제한적

---

## 6. 도구 선택 가이드

| 상황 | 추천 도구 | 이유 |
|------|-----------|------|
| 단순한 1:1 자동화 (알림, 저장 등) | Zapier | 빠르고 쉽게 설정 가능 |
| 조건 분기가 많은 복잡한 워크플로우 | Make | Router로 하나의 시나리오에서 관리 |
| 실시간 처리가 중요한 업무 | Zapier | 폴링 지연 없이 즉시 실행 |
| 무료로 많은 실행 횟수가 필요한 경우 | Make | 월 1,000회로 Zapier의 10배 |
| 다양한 앱 연동이 필요한 경우 | Zapier | 6,000개 이상의 앱 지원 |
| 데이터 가공·변환이 필요한 경우 | Make | 내장 함수 및 고급 처리 기능 제공 |

> **결론:** 단순 자동화 입문에는 Zapier, 실무 수준의 복잡한 자동화에는 Make가 적합하다.

## 7. 과제 목표 달성 확인

### 기능 요구사항 충족 여부

| 요구사항 | Make | Zapier | 비고 |
|----------|------|--------|------|
| Trigger 1개 이상 | ✅ | ✅ | Google Forms - 새 응답 제출 |
| Action 2개 이상 | ✅ | ✅ | Google Sheets + Discord |
| 조건 분기 1개 이상 | ✅ | ✅ | Router / Filter by Zapier |
| 각 분기 1회 이상 실행 | ✅ | ✅ | 합격/불합격 케이스 각각 실행 확인 |
| 서로 다른 도구 2개 사용 | ✅ | ✅ | Make + Zapier |
| 동일한 워크플로우 구조 | ✅ | ✅ | 동일한 퀴즈 시스템으로 구현 |
| 비교 항목 5개 이상 | ✅ | - | 10개 항목 비교 |

### 학습 목표 달성 여부

**① Trigger와 Action의 개념**
- **Trigger**: 자동화를 시작시키는 이벤트. 본 프로젝트에서는 Google Form에 응답이 제출되는 순간이 Trigger
- **Action**: Trigger 이후 자동으로 실행되는 작업. 본 프로젝트에서는 Sheets 기록과 Discord 알림 전송

**② 조건 분기(Filter/Router)의 역할**
- 조건 분기는 데이터의 특정 값을 기준으로 이후 실행 경로를 나누는 역할
- Make의 Router는 하나의 흐름에서 여러 경로로 분기
- Zapier의 Filter는 조건 미충족 시 해당 Zap의 실행을 중단

**③ 서로 다른 자동화 도구의 특징 비교**
- 위 비교표(10개 항목) 참조

**④ 특정 업무에 적합한 도구 선택**
- 복잡한 분기 처리 → Make 선택
- 단순 알림 자동화 → Zapier 선택
- 도구 선택 가이드 참조

**⑤ 자동화 흐름을 단계별로 설명**
```
1단계: 응시자가 Google Form에 이름과 점수를 입력하고 제출
2단계: Trigger 감지 → 자동화 시작
3단계: 조건 분기 → 점수 8점 이상이면 합격 경로, 미만이면 불합격 경로
4단계: Google Sheets에 이름, 점수, 결과 자동 기록
5단계: Discord Webhook으로 관리자에게 결과 알림 전송
```

# 노코드 자동화 도구 비교 분석 보고서
### Make vs Zapier — 상식 퀴즈 자동화 워크플로우 구현

---

## 1. 프로젝트 개요

### 1-1. 사용 도구
| 도구 | 역할 | 무료 플랜 제한 |
|------|------|----------------|
| **Make** | 시나리오 기반 자동화 | 월 1,000 operations |
| **Zapier** | Zap 기반 자동화 | 월 100 tasks, 5 Zaps |
| **Google Forms** | 퀴즈 응시 입력 수집 | 무제한 |
| **Google Sheets** | 응시 결과 기록 저장 | 무제한 |
| **Discord Webhook** | 합격/불합격 알림 발송 | 무제한 |

### 1-2. 워크플로우 개요
```
[응시자] Google Form 제출
           ↓
    점수 데이터 수신
           ↓
   ┌───────┴────────┐
   │ 8점 이상 (합격) │  │ 7점 이하 (불합격) │
   └───────┬────────┘  └────────┬──────────┘
           ↓                    ↓
   Google Sheets 기록    Google Sheets 기록
           ↓                    ↓
  Discord 합격 알림     Discord 불합격 알림
```

---

## 2. 워크플로우 설계

### 2-1. 퀴즈 구성
- **문항 수**: 10문항 (상식 퀴즈)
- **합격 기준**: 8점 이상 (80%)
- **수집 필드**: 응시자 이름, 점수

### 2-2. 자동화 처리 흐름
| 단계 | 처리 내용 |
|------|-----------|
| ① 트리거 | Google Form 응답 제출 감지 |
| ② 분기 | 점수 조건에 따라 합격 / 불합격 경로 분리 |
| ③ 기록 | Google Sheets에 이름·점수·결과 저장 |
| ④ 알림 | Discord 웹훅으로 관리자에게 결과 알림 |

---

## 3. 구현 과정

### 3-1. Make 구현

**구성 방식**: 단일 시나리오 + Router 모듈로 분기

| 순서 | 모듈 | 설명 |
|------|------|------|
| 1 | Google Forms — Watch Responses | Form 응답 트리거 |
| 2 | Router | 합격/불합격 경로 분기 |
| 3-A | Google Sheets — Add Row (합격) | 합격자 시트에 기록 |
| 3-B | Google Sheets — Add Row (불합격) | 불합격자 시트에 기록 |
| 4-A | Discord — Send Webhook (합격) | 합격 알림 전송 |
| 4-B | Discord — Send Webhook (불합격) | 불합격 알림 전송 |

## 4. 도구 비교 분석

### 4-1. 핵심 기능 비교표

| 비교 항목 | Make | Zapier |
|-----------|------|--------|
| **UI 방식** | 시각적 캔버스 (노드 연결) | 단계별 리스트 |
| **분기 처리** | Router 모듈 (1개 시나리오) | Filter + Zap 분리 (2개 Zap) |
| **무료 플랜** | 월 1,000 operations | 월 100 tasks, 5 Zaps |
| **트리거 주기** | 15분 간격 (무료) | 15분 간격 (무료) |
| **앱 연동 수** | 1,500+ | 6,000+ |
| **학습 난이도** | 중간 (시각적이나 개념 필요) | 낮음 (직관적 단계 구성) |
| **에러 처리** | 모듈별 오류 핸들러 설정 가능 | 기본 오류 알림 제공 |
| **실행 로그** | 시나리오별 상세 로그 | Task History 제공 |
| **데이터 가공** | 내장 함수·수식 풍부 | 기본 수준 |
| **가격 정책** | 기능 중심 (operations 과금) | Zap 수 + task 수 과금 |

### 4-2. 분기 처리 방식 비교

| 구분 | Make | Zapier |
|------|------|--------|
| **방식** | Router 모듈로 1개 시나리오 내 분기 | 조건별 Zap을 별도로 생성 |
| **장점** | 전체 흐름을 한눈에 파악 가능 | 각 조건이 독립적으로 관리됨 |
| **단점** | 복잡해지면 캔버스가 혼잡해짐 | Zap 수 증가 → 무료 플랜 한계 도달 빠름 |

## 5. 장단점 정리

### 5-1. Make
| 구분 | 내용 |
|------|------|
| ✅ 장점 | 시각적 흐름 파악 용이, 복잡한 분기·반복 처리 강점, 무료 플랜 operations 여유로움 |
| ❌ 단점 | 초기 학습 곡선 존재, 앱 연동 수 Zapier 대비 적음 |

### 5-2. Zapier
| 구분 | 내용 |
|------|------|
| ✅ 장점 | 직관적인 단계별 UI, 앱 연동 수 최다(6,000+), 빠른 설정 가능 |
| ❌ 단점 | 무료 플랜 task 수 제한 빠름(100), 복잡한 분기 시 Zap 수 증가 |

---

## 6. 도구 선택 가이드

| 상황 | 추천 도구 | 이유 |
|------|-----------|------|
| 복잡한 분기·조건 처리 | **Make** | Router로 한 시나리오에서 처리 가능 |
| 빠른 단순 자동화 | **Zapier** | 직관적 UI, 빠른 설정 |
| 다양한 앱 연동 필요 | **Zapier** | 6,000+ 앱 지원 |
| 무료로 많은 실행 필요 | **Make** | 월 1,000 operations 제공 |
| 팀 협업·공유 | **Make** | 시나리오 시각화로 공유 용이 |

### 7-2. 학습 목표 달성 서술

본 프로젝트를 통해 노코드 자동화 도구인 **Make**와 **Zapier**를 동일한 워크플로우(상식 퀴즈 자동화)에 적용하여 두 도구의 구조적 차이를 직접 경험하였다.

Make는 **시각적 캔버스 기반**으로 Router 모듈을 활용한 분기 처리가 직관적이며, 복잡한 자동화 흐름을 하나의 시나리오에서 관리할 수 있다는 강점을 확인하였다. 반면 Zapier는 **단계별 리스트 방식**으로 초보자도 빠르게 설정할 수 있으나, 조건 분기 시 Zap을 별도로 생성해야 하므로 무료 플랜의 Zap 수 제한에 빠르게 도달할 수 있음을 파악하였다.

두 도구 모두 **Google Forms → 조건 분기 → Google Sheets 기록 → Discord 알림**이라는 동일한 목적을 달성할 수 있었으며, 사용 목적과 규모에 따라 적합한 도구를 선택하는 것이 중요함을 학습하였다.

# 프로젝트 1 비교분석보고서
## 퀴즈 채점 자동 알림 시스템 (Make vs Zapier)

---

## 1. 프로젝트 개요

| 항목 | 내용 |
|------|------|
| **프로젝트명** | 퀴즈 채점 자동 알림 시스템 |
| **목적** | 구글 폼으로 제출된 퀴즈 응답을 자동 채점하고, 결과를 Discord로 알림 |
| **데이터 흐름** | Google Forms → Google Sheets → 채점 로직 → Discord 알림 |
| **합격 기준** | 정답 **8개 이상 → PASS** / **8개 미만 → FAIL** |
| **비교 도구** | Make (구 Integromat) vs Zapier |

### 워크플로우 구조
```
[Trigger] 구글 폼 응답 제출 (Google Sheets 새 행 추가)
   ▼
[Action] 정답 개수 집계 (채점 로직)
   ▼
[Router / Filter] 정답 개수 조건 분기
   ├─ 8개 이상  → Discord "PASS 🎉" 메시지 발송
   └─ 8개 미만  → Discord "FAIL 😢" 메시지 발송
```

## 3. Zapier 구현

> ⚠️ **Zapier의 구조적 특징**: 하나의 Zap(Path/조건 분기)에서 **여러 조건을 동시에 한 번에 넣기 어려움**.
> 따라서 **PASS 조건**과 **FAIL 조건**을 각각 별도의 경로(Path)로 나누어 구성해야 하므로 화면이 2개로 분리됨.

- 조건이 늘어날수록 관리해야 할 경로(화면)가 많아짐 → **본 프로젝트에서 발견한 단점**

## 4. 핵심 비교 분석

| 비교 항목 | Make | Zapier |
|-----------|------|--------|
| **UI/UX** | 노드(선) 기반 시각적 구성, 흐름 파악 쉬움 | 단계별(Step) 리스트 방식, 초보자 친화적 |
| **설정 난이도** | 다중 조건 분기가 한 화면에서 가능 (상대적 편리) | 조건마다 경로 분리 필요 (다소 번거로움) |
| **조건 분기** | Router 1개로 여러 갈래 분기 가능 | 한 Zap에 여러 조건 동시 처리 어려움 → **경로 분리 필요** |
| **연동 범위** | 1,000+ 앱 연동 | 6,000+ 앱 연동 (연동 앱 수는 더 많음) |
| **무료 플랜** | 월 1,000 operations | 월 100 tasks (상대적으로 적음) |
| **실행 로그** | 상세한 실행 히스토리 + 각 모듈별 데이터 확인 | Task History로 성공/실패 확인 |
| **과금 방식** | **작업 실행 횟수당 차감 (operations 기반)** | **작업 실행 횟수당 차감 (tasks 기반)** |

## 5. 과금 방식 상세 (직접 확인 필요 ⚠️)

> **아래 내용은 반드시 공식 요금 페이지에서 최신 정보를 재확인하세요.**
> 요금 정책은 자주 바뀌므로, 보고서 제출 전 확인 권장드립니다.

| 도구 | 과금 단위 | 개념 |
|------|-----------|------|
| **Make** | **Operations(작업 수) 당 차감** | 모듈이 1번 실행될 때마다 1 operation 소모. 즉 **"실행 횟수당" 차감** 방식에 가까움 |
| **Zapier** | **Tasks(작업 수) 당 차감** | Zap의 액션이 1번 성공 실행될 때마다 1 task 소모. 역시 **"실행 횟수당" 차감** |

### 💡 정정: "Make=횟수당, Zapier=상시"는 정확하지 않아요!
- **두 도구 모두 기본적으로 "실행 횟수(작업 수) 기반"** 과금입니다.
- 다만 **차이점**은:
  - **Make**: 모듈(단계) 하나하나 실행마다 operation 차감 → 워크플로우가 길수록 더 많이 소모
  - **Zapier**: 트리거는 무료, **액션(task) 실행 시**에만 차감 → 단계 수보다 성공한 액션 수 기준
- **"상시 돌아간다"**는 개념보다는, 두 도구 모두 **트리거가 감지될 때마다 실행되고 그만큼 차감**되는 구조로 이해하는 게 정확합니다.

## 6. 결론

| 관점 | 추천 도구 |
|------|-----------|
| **복잡한 다중 조건 분기** | Make (Router 한 화면에서 관리) |
| **초보자 / 간단한 자동화** | Zapier (직관적 단계별 설정) |
| **연동 앱 다양성** | Zapier (6,000+ 앱) |
| **긴 워크플로우 비용 효율** | 케이스별 상이 (직접 계산 권장) |

### 본 프로젝트에서 느낀 점
- Make는 **조건 분기를 한 화면에서 시각적으로** 처리할 수 있어 편리했다.
- Zapier는 **조건마다 경로를 나눠야 해서** PASS/FAIL 구성 화면이 2개로 분리되는 번거로움이 있었다.
- 두 도구 모두 **실행 횟수 기반 과금**이므로, 워크플로우 설계 시 불필요한 단계를 줄이는 것이 비용 절감에 중요하다.

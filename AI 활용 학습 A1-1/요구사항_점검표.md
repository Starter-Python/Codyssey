## 2. 기능별 요구사항과 만족 방법

| 요구사항 (무엇) | 어떻게 만족했나 (동작 + 예외 처리) | 구현 위치 |
| --- | --- | --- |
| 메뉴 출력·선택·오입력 안내·종료 후 메뉴 복귀 | `show_menu()`가 번호+이름 14줄 출력. `get_menu_choice()`가 `MENU_OPTIONS` 키 검사를 통과할 때까지 재요청하며 오입력 시 안내 문구 출력. 각 기능 종료 후 `while True` 처음으로 복귀, `14`만 `return` 종료 | `show_menu`, `get_menu_choice`, 메뉴 `14`, `run_menu_loop` |
| 기본 데이터 구조: `list[dict]` + 5개 필드 | 전체는 `list[Prompt]`, 한 건은 `TypedDict`(`title/content/category/favorite/view_count`) 딕셔너리. 순서가 필요해서 `list`, 필드 구분을 위해 `dict` 선택 | `DEFAULT_PROMPTS`, `Prompt` 클래스 정의 |
| 추가: 빈값 재입력, 카테고리 선택/직접입력, 즉시 반영 | 제목·내용은 `get_non_empty_input()`이 `strip()` 후 빈값이면 재요청. 카테고리는 `choose_category()`에서 번호 선택 또는 `0` 직접입력. 중복(제목+내용 완전일치, 공백·대소문자 무시)이 아니면 `append`, 바로 목록에 보임 | `add_prompt`, `get_non_empty_input`, `choose_category`, `find_duplicate_prompt` |
| 목록: 번호·제목·카테고리·⭐·조회수, 빈 목록 안내 | `format_prompt_summary()`가 `"{번호}. {제목} \| 카테고리: ... \| 즐겨찾기: ⭐ \| 조회: N"` 1줄 포맷 전담. 항목 없으면 “저장된 프롬프트가 없습니다.” 출력 | `show_prompt_list`, `format_prompt_summary` |
| 카테고리 조회: 없으면 안내, 직접입력 카테고리도 조회 가능 | `filter_prompts_by_category()`로 정확히 일치하는 항목만 추출. `view_categories`가 `CATEGORIES` + 기존 데이터의 커스텀 카테고리를 합쳐 보여주므로 직접입력값도 이후 조회 가능. 결과 없으면 안내 후 복귀 | `show_prompts_by_category`, `filter_prompts_by_category` |
| 검색: 제목·내용 부분일치, 없으면 안내 | `find_prompts()`가 `keyword.casefold() in title.casefold() or keyword.casefold() in content.casefold()` 로 대소문자 무시 부분검색. 빈 결과는 `[]` 반환 후 “검색 결과가 없습니다.” 안내 | `find_prompts`, `search_prompts` |
| 상세: 전 필드 표시 + 조회수 기록, 잘못된 번호 안내 | 번호→`get_prompt_index()`로 1-based를 0-based로 변환(범위 밖은 `None` + 안내). 정상이면 제목·내용·카테고리·⭐·조회수 전부 출력 후 `view_count += 1` | `show_prompt_detail`, `get_prompt_index`, `is_valid_prompt_number` |
| 즐겨찾기 토글·모아보기 | 별도 목록 없이 `prompt["favorite"] = not prompt["favorite"]` 로 뒤집고 상태 문구 출력. 모아보기는 `favorite is True`인 항목만 필터링, 없으면 안내 | `toggle_favorite`, `show_favorites` |
| 삭제: 확인 후 삭제·취소·빈 목록 안내 | 번호 선택 → 제목·카테고리 보여주고 `y/n` 확인. `y`면 `pop(index)`, `n`·기타면 취소. 빈 목록이면 번호 입력 전에 안내하고 복귀 | `delete_prompt` |
| 수정: Enter 유지·중복 차단 | 번호 선택 → 새 제목·내용(Enter 입력 시 기존 유지) → 카테고리 변경 여부 → 수정 결과가 기존 다른 항목과 제목+내용 완전중복이면 취소, 아니면 키 대입으로 덮어쓰기 | `edit_prompt` |
| 조회수 Top 5 | `get_top_prompts()`가 `sorted(prompts, key=view_count, reverse=True)[:5]` 로 내림차순 정렬. 상세 보기를 열 때마다 조회수가 쌓이므로 많이 본 항목이 상위에 옴 | `get_top_prompts`, `show_top_prompts` |
| JSON 저장·불러오기 (보너스) | `save_prompts()`는 `json.dump(ensure_ascii=False, indent=2)` 로 한글 그대로 저장. `load_prompts_into()`는 파일 없음·깨짐 시 안내 후 기본 유지, `normalize_loaded_prompt()`가 빠진 필드를 기본값으로 채워 구버전 파일도 읽힘 | `save_prompts`, `load_prompts`, `load_prompts_into` |
| Markdown 내보내기 (보너스) | 카테고리별로 `## 카테고리명`, 항목별로 `### 번호. 제목` + 내용·⭐·조회수를 묶어 `prompts_by_category.md` 생성. 형식을 바꾸려면 이 함수 1곳만 수정 | `export_prompts_markdown` |
| 입력 중단·비대화형 안전 종료 | 모든 `input()`은 `read_user_input()`을 경유, `EOFError`·`KeyboardInterrupt`를 `UserInputCancelled`로 통일 후 `main()`에서 “입력이 중단되어 프로그램을 종료합니다.”로 마무리. `is_interactive_terminal()`이 Output·Debug Console 실행을 감지하면 메뉴 대신 터미널 실행 안내 | `read_user_input`, `is_interactive_terminal`, `main` |

## 4. 평가 답변 (항목 1~5 핵심)

**항목 1. 기능:** 요구사항은 메뉴 `1`~`14`가 오류 없이 동작하고 추가가 즉시 목록에 반영되는 것이다. `run_menu_loop` 분기로 연결했고, 추가는 `append` 직후 목록에서 확인 가능하며, 검색은 `casefold()` 부분 일치, 즐겨찾기는 불리언 토글, 삭제는 `y` 확인 후 `pop`, 수정은 Enter 유지 방식으로 만족했다. 병합 커밋 `5aeef4c`가 브랜치 요구사항의 증거다.

**항목 2. 구조:** 요구사항은 함수 분리다. 데이터는 `list[Prompt]`, 접근은 `enumerate` 순회 + 키 접근, 갱신은 키 대입으로 구현했다. 입력 검증은 `get_non_empty_input`(빈값), `is_valid_prompt_number`+`get_prompt_index`(범위·변환), `get_menu_choice`(메뉴 범위)에서 각각 처리한다. 커밋은 `feat/docs/test/refactor/merge`처럼 기능 단위로 나눠 10개 이상 유지한다.

**항목 3. 원리:** 요구사항은 자료구조·반복·종료·검색·브랜치 이해다. 순서가 있는 모음이라 `list`, 서로 다른 필드를 묶으니 `dict`를 썼다. 종료 시점을 알 수 없어 `while True`로 반복하고, `14`·`return`으로 정상 종료, `EOF`·`Ctrl+C`는 `UserInputCancelled`로 안전 종료한다. 검색식은 `keyword in title or keyword in content`이며, 브랜치는 목록 기능을 `feature/a1-1-prompt-list`에서 완성·테스트 후 `main`에 병합했다.

**항목 4. 심화:** 요구사항은 영속화·예외·중복·충돌·확장성이다. 영속화는 표준 `json`으로 구현했다(`save_prompts`·`load_prompts_into`, 없거나 깨지면 안내 후 기본 유지, `ensure_ascii=False`). 같은 제목은 내용이 다르면 다른 버전으로 허용하고 완전 중복만 차단한다. 충돌은 `git status` 확인 → `<<<<<<<` 표식 제거·내용 선택 → `add`·`commit`·테스트 순으로 해결한다. 카테고리 변경은 `CATEGORIES`만 고치면 관련 함수가 함께 반영된다.

**항목 5. 보너스:** 요구사항 외 가산점이다. 전부 구현됨. JSON 저장·불러오기, 카테고리별 Markdown 내보내기, 수정·삭제, 상세 보기 조회수(`view_count`) 기록, 조회수 Top 정렬(`sorted(reverse=True)`)이 해당한다.

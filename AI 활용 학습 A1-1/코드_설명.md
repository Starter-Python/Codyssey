# 코드 설명 | `prompt_manager.py`를 위에서 아래로 풀어 읽기

이 문서는 `prompt_manager.py`(약 600줄)를 처음부터 끝까지 따라가며,
각 코드가 `무엇을·왜·어떻게` 하는지 설명합니다.
`외울 말`은 평가 때 그대로 말하면 되는 한 줄 요약입니다.

## 0. 읽는 순서와 전체 지도

```text
1~16   모듈 설명·import
19~44  데이터 설계도(Prompt, 상수, 기본 데이터)
119~134 메뉴표(MENU_OPTIONS)
137~157  시작 준비(create_initial_prompts, 터미널 확인)
160~211  입력 처리(read, 빈값, 번호, 카테고리, 중복 탐색)
238~341  핵심 기능(추가·목록·카테고리·검색·상세)
361~524  즐겨찾기·삭제·수정·Top·저장·내보내기

```

**외울 말:** “위에서 아래로 데이터 정의→입력 검증→기능 함수→메뉴 반복→시작점 순서이며, `main`은 연결만 하고 실제 일은 각 함수가 합니다.”

## 1. 맨 위: 모듈 설명과 import (1~16줄)

파일 첫 큰따옴표 덩어리(docstring)가 이 파일의 역할을 선언합니다.
그 아래 표준 라이브러리만 불러옵니다.

```python
from copy import deepcopy
import json
from pathlib import Path
import sys
from typing import TypedDict
```

| import | 왜 필요한가 |
| --- | --- |
| `deepcopy` | 기본 데이터를 통째 복사해 실행 간 오염 방지 |
| `json` | 보너스 저장·불러오기 (`dump`·`load`) |
| `Path` | 저장 파일 경로 다루기 |
| `sys` | 터미널 입력 가능 여부(`isatty`) 확인 |
| `TypedDict` | 딕셔너리 키 구성을 코드에 명시 |

**외울 말:** “외부 패키지 없이 표준 라이브러리만 쓰므로 `pip install`이 필요 없습니다.”

## 2. 데이터 설계도: Prompt와 상수 (19~44줄)

```python
class Prompt(TypedDict):
    title: str
    content: str
    category: str
    favorite: bool
    view_count: int
```

`Prompt`는 객체를 찍어내는 클래스가 아니라 **딕셔너리가 지켜야 할 키 목록**입니다.
실제 한 건은 아래처럼 생겼습니다.

```python
{"title": "블로그 초안 작성", "content": "...", "category": "텍스트 생성",
 "favorite": True, "view_count": 0}
```

| 키 | 뜻 | 쓰임 |
| --- | --- | --- |
| `title` | 짧은 이름 | 목록·검색·상세·수정 |
| `content` | 전문 | 검색·상세·수정 |
| `category` | 분류 | 추가·수정·조회·내보내기 |
| `favorite` | ⭐ 여부 | 토글·모아보기 |
| `view_count` | 조회수 | 상세 열 때마다 +1, Top 정렬 기준 |

`CATEGORIES`(37줄)는 바뀌지 않는 튜플 6개, `DEFAULT_PROMPTS`(46줄)는 시작용 예시 10개입니다.

**외울 말:** “전체를 `list`에, 한 건을 `dict`에 담는 `list[dict]` 구조입니다. 순서는 리스트가, 필드 구분은 딕셔너리가 맡습니다.”

## 3. 메뉴표 MENU_OPTIONS (119~134줄)

```python
MENU_OPTIONS = {"1": "프롬프트 추가", ..., "14": "종료"}
```

키를 문자열로 둔 이유는 `input()`이 항상 문자열을 돌려주기 때문입니다.
사용자가 `2`를 눌러도 프로그램 안에서는 `"2"`가 됩니다.
`show_menu()`는 이 사전 순서대로, `get_menu_choice()`는 이 사전 키 검사로 동작하므로,
메뉴를 늘리려면 사전 1곳과 `run_menu_loop` 분기 1곳만 고치면 됩니다.

## 4. 시작 준비: 복사와 터미널 확인 (137~157줄)

```python
def create_initial_prompts() -> list[Prompt]:
    return deepcopy(DEFAULT_PROMPTS)
```

얕은 복사는 리스트 안 딕셔너리를 공유해서, 즐겨찾기를 바꾸면 원본까지 바뀝니다.
`deepcopy()`는 안까지 전부 새로 복사하므로 **실행마다 독립된 목록**이 생기고,
종료 후 재실행하면 항상 기본 10개로 시작합니다. 테스트끼리 섞이지 않는 이유도 같습니다.

```python
def is_interactive_terminal() -> bool:
    return sys.stdin.isatty() and sys.stdout.isatty()
```

`input()`이 필요하므로 통합 터미널인지 먼저 봅니다.
Output·Debug Console처럼 입력이 안 되는 곳이면 메뉴 대신 실행 방법을 안내하고 끝냅니다.

**외울 말:** “깊은 복사로 실행 독립성을, 터미널 확인으로 입력 안정성을 보장합니다.”

## 5. 입력 처리 함수 (160~211줄)

모든 입력은 `read_user_input()`을 거칩니다.

```python
def read_user_input(prompt: str) -> str:
    try:
        return input(prompt)
    except (EOFError, KeyboardInterrupt) as error:
        raise UserInputCancelled from error
```

입력 스트림 종료와 `Ctrl+C`를 전용 예외 하나로 통일했기 때문에,
어디서 끊겨도 `main()`에서 “입력이 중단되어 프로그램을 종료합니다.” 한 줄로 마무리됩니다.

| 함수 | 하는 일 | 왜 따로 뺐나 |
| --- | --- | --- |
| `get_non_empty_input` (169) | `strip()` 후 빈값이면 재요청 | 제목·내용·검색어 무결성을 한곳에서 보장 |
| `is_valid_prompt_number` (179) | 숫자인지 + 범위 안인지 검사 | `IndexError`를 사전 차단 |
| `get_prompt_index` (185) | 통과한 번호를 0시작 위치로 변환 | 화면 번호(1~)와 리스트 위치(0~)의 간극 해소 |
| `choose_category` (199) | 기본 번호 선택 또는 `0` 직접 입력 | 입력 로직 재사용·검증 분리 |
| `normalize_prompt_text` (216) + `find_duplicate_prompt` (222) | 공백·대소문자 정리 후 제목+내용 일치 탐색 | 중복 판단 기준을 테스트 가능하게 분리 |

화면 번호와 리스트 위치의 관계는 이렇습니다.

```text
화면: 1, 2, 3
내부: 0, 1, 2
```

## 6. 추가와 중복 방지 (238줄)

```python
제목·내용 입력 → 중복 검사 → 카테고리 선택 → append
```

새 항목은 `favorite=False, view_count=0`으로 시작합니다.
중복은 **제목과 내용이 모두 같을 때만** 차단하고, 앞뒤·연속 공백과 영어 대소문자는 무시합니다.

| 경우 | 결과 | 이유 |
| --- | --- | --- |
| 둘 다 같음 | 차단 + 안내 | 같은 항목이 쌓이는 것 방지 |
| 하나라도 다름 | 등록 | 다른 버전일 수 있음 |
| 공백·대소문자만 다름 | 차단 | 실수성 차이로 간주 |

**외울 말:** “같은 목적의 다른 버전은 살리고, 완전 중복만 막는 것이 가장 안전한 기준입니다.”

## 7. 보여주기: 목록·카테고리·검색·상세 (263~341줄)

| 함수 | 고르는 기준 | 결과 |
| --- | --- | --- |
| `show_prompt_list` (274) | 없음 | 전 항목 한 줄 요약 |
| `show_prompts_by_category` (316) | 카테고리명 일치 | 맞는 항목 요약 |
| `search_prompts` (335) | 키워드가 제목·내용에 포함 | 일치 항목 요약 |
| `show_prompt_detail` (342) | 번호 | 전 필드 + 조회수 +1 |
| `show_top_prompts` (445) | 조회수 상위 | Top 5 요약 |

한 줄 요약은 `format_prompt_summary()`(263)가 전담합니다.

```python
f"{number}. {제목} | 카테고리: ... | 즐겨찾기: ⭐ | 조회: {view_count}"
```

형식을 바꾸고 싶으면 이 함수 1곳만 고치면 목록·검색·즐겨찾기 화면에 함께 반영됩니다.
검색의 핵심은 이 두 줄입니다.

```python
normalized_keyword in prompt["title"].casefold()
or normalized_keyword in prompt["content"].casefold()
```

상세 보기는 보여주는 김에 `view_count`를 1 올리므로, 많이 열어본 항목이 Top에 오르는 구조입니다.
결과가 비면 “저장된 프롬프트가 없습니다.”가 나옵니다.

## 8. 즐겨찾기·삭제·수정 (361~437줄)

즐겨찾기는 별도 목록을 두지 않습니다.

```python
prompt["favorite"] = not prompt["favorite"]
```

같은 메뉴로 추가·해제를 겸하고, 모아보기는 참인 항목만 골라 보여줍니다.

삭제(387)는 번호 → 제목·카테고리 확인 → `y`면 `pop`, 그 외면 취소입니다.
수정(407)은 번호 → 새 제목·내용(Enter면 유지) → 카테고리 변경 여부 → 중복이면 취소, 아니면 덮어쓰기입니다.
빈 목록이면 번호 입력 전에 안내하고 메뉴로 돌아옵니다.

## 9. 저장과 내보내기 (452~524줄)

```python
save_prompts()          # json.dump(ensure_ascii=False, indent=2)
load_prompts_into()     # 읽어서 현재 목록에 덮어쓰기
export_prompts_markdown()  # 카테고리별 ##, 제목별 ### 문서 생성
```

JSON을 고른 이유는 `list[dict]`와 1:1로 맞고 내장 모듈이라 설치가 필요 없기 때문입니다.
불러올 때 `normalize_loaded_prompt()`가 빠진 필드를 기본값으로 채우므로,
옛날 파일(예: `view_count` 없음)도 깨지지 않고 읽힙니다.
파일이 없거나 깨지면 안내 후 기본 데이터로 계속합니다.
저장 파일(`prompts.json`, `prompts_by_category.md`)은 `.gitignore`에 넣어 GitHub에 올리지 않습니다.

## 10. 메뉴 반복과 시작점 (526~598줄)

```python
while True:
    show_menu()
    choice = get_menu_choice()
    if choice == "1":
        add_prompt(prompts)
    ...
    elif choice == "14":
        return
```

기능이 끝나면 반복문 처음으로 돌아가 메뉴가 다시 뜹니다.
횟수를 알 수 없어 `while True`를 쓰고, `14`·`return`이 정상 종료,
`EOF`·`Ctrl+C`가 예외 종료, 오입력이 안내 후 반복입니다.

```python
if __name__ == "__main__":
    main()
```

이 조건 덕분에 테스트가 `import`할 때는 메뉴가 실행되지 않고 함수만 빌려 쓸 수 있습니다.
`main()`의 일은 세 가지입니다: 터미널 확인 → 목록 복사 → 반복 시작(중단 시 안내 종료).

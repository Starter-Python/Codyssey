## 2. Python 기초

### 변수·함수·모듈
* **변수:** 값을 담는 이름. 예: `prompts = [...]`.
* **함수:** 입력→처리→출력을 묶은 단위. 외울 말: “한 함수는 한 역할만 맡게 나눴습니다.”
* **모듈·import:** 남이 만든 기능을 불러쓰는 것. 이 과제는 `copy`·`json`·`sys`·`typing` 표준 모듈만 씁니다.
* **표준 라이브러리:** 설치 없이 쓰는 기본 기능 모음. 외울 말: “외부 패키지 없이 표준 라이브러리만으로 동작합니다.”

### 조건문·반복문
* **조건문(`if/elif/else`):** 메뉴 번호별 분기에 사용. 외울 말: “선택값에 따라 해당 함수로 분기합니다.”
* **`while True`:** 횟수를 모를 때 쓰는 무한 반복. 메뉴 전체, 빈값 재입력, 번호 재입력에 사용. 외울 말: “종료 조건이 될 때까지 계속돼야 해서 `while`을 썼고, `14`·`return`으로 나옵니다.”
* **`enumerate`:** 번호와 값을 함께 꺼내는 반복. 목록에 `1.`부터 붙일 때 사용.

### 리스트·딕셔너리
* **`list`:** 순서 있는 모음. 전체 프롬프트 보관. 외울 말: “등록 순서 보장과 메뉴 번호 매핑이 쉽습니다. 단점은 검색에 전체 순회가 필요하다는 점입니다.”
* **`dict`:** 키-값 묶음. 한 프롬프트(`title/content/category/favorite/view_count`) 보관. 외울 말: “서로 다른 필드를 이름으로 구분하고 O(1)로 접근합니다. 단점은 스키마 강제가 없어 `TypedDict`·테스트로 보완했다는 점입니다.”
* **`TypedDict`:** 딕셔너리 키 구성을 코드에 명시한 것.
* **`append`·`pop`:** 끝에 추가·꺼내어 삭제. 추가·삭제의 핵심 동작.

### 문자열·입력 처리
* **`input()`:** 키보드 한 줄 입력. 항상 문자열 반환 → 메뉴 키도 문자열(`"1"`~`"14"`).
* **`strip()`:** 앞뒤 공백 제거. 공백만 입력한 빈값 판정에 사용.
* **`isdigit()` + 범위 검사:** 번호가 숫자이며 목록 안에 있는지 확인 (`is_valid_prompt_number`).
* **`casefold()`:** 대소문자 무시 비교. 검색· clos중복 판정에 사용. 외울 말: “`lower()`보다 다국어 처리에 강합니다.”
* **`in`:** 부분 포함 검사. “제목 또는 내용 포함” 검색의 핵심.

### 복사·파일·예외
* **`deepcopy`:** 리스트 안 딕셔너리까지 통째 복사. 외울 말: “실행 간 데이터 오염을 막아 재실행하면 기본 10개로 시작합니다.”
* **JSON(`json.dump/load`):** `list[dict]`를 파일에 저장·복원하는 형식. `ensure_ascii=False`로 한글 보존. 외울 말: “내장 모듈이라 추가 설치 없이 영속화할 수 있습니다.”
* **Markdown 내보내기:** 사람이 읽는 문서용 출력. 카테고리별 `##`, 제목별 `###`로 묶음.
* **예외(`EOFError`·`KeyboardInterrupt`):** 입력 끊김·`Ctrl+C`. `read_user_input`에서 `UserInputCancelled` 하나로 통일 후 안내 종료.
* **`if __name__ == "__main__"`:** 직접 실행 때만 메뉴 시작, `import` 때는 함수만 빌려쓰게 하는 문.

### 테스트 용어
* **`unittest`:** 표준 테스트 도구. `patch`로 `input()`을 가짜 입력으로 대체, `StringIO`로 `print()`를 캡처해 검증.
* **`py_compile`:** 문법 오류만 빠르게 확인하는 검사.

## 6. 평가 항목별 상세 답변 (외울 말 + 실습 근거)

아래 7개는 제출·평가에서 그대로 묻는 항목이다. 각 항목은 `정의(외울 말) → 실제手順 → 이 과제에서의 근거` 순서로 답한다.

### 6-1. VSCode에서 Python 파일을 생성하고 실행할 수 있다.

**외울 말:** “VSCode에서 `.py` 파일을 만들고, 반드시 통합 터미널에서 `python3`으로 실행합니다.”

**자세한 답변:**
1. 파일 생성: VSCode 탐색기에서 `AI 활용 학습 A1-1` 폴더 우클릭 → 새 파일 → `prompt_manager.py`처럼 `.py` 확장자로 저장. 또는 터미널에서 `touch prompt_manager.py`.
2. 코드 작성: Python 확장(Microsoft 제공)을 설치하면 문법 강조·오류 밑줄·인터프리터 선택이 가능. `Ctrl+Shift+P → Python: Select Interpreter`에서 Python 3.10 이상 선택.
3. 실행: 반드시 `Terminal > New Terminal`에서 실행한다. `Output`·`Debug Console`은 `input()`을 받을 수 없어 안내 문구만 나오고 멈춘다.
   ```bash
   cd "AI 활용 학습 A1-1"
   python3 prompt_manager.py
   ```
4. 이 과제 근거: `prompt_manager.py`는 `input()` 기반 메뉴 프로그램이라 `is_interactive_terminal()`로 터미널 여부를 먼저 검사한다. 비대화형이면 메뉴 대신 실행 안내 후 종료한다. `README.md`·`실행_가이드.md`에도 “통합 터미널에서 실행”을 명시했다.

### 6-2. 터미널에서 Python/Git 버전을 확인하고 필요한 설정을 점검할 수 있다.

**외울 말:** “`python3 --version`, `git --version`, `git config` 세 줄로 실행 조건과 신원을 점검합니다.”

**자세한 답변:**
1. Python 확인: `python3 --version` → `Python 3.12.3`처럼 3.10 이상이면 통과. 없으면 Python 재설치 후 VSCode 재시작.
   ```bash
   python3 --version
   python3 -c 'print("Hello")'
   ```
   두 번째 줄은 인터프리터 자체가 동작하는지 보는 최소 테스트다.
2. Git 확인:
   ```bash
   git --version
   git config --global user.name "이름"
   git config --global user.email "메일"
   git config --global --list
   git branch --show-current
   ```
   `user.name/email`이 비어 있으면 커밋 저자가 기록되지 않으므로 최초 1회는 반드시 설정한다. `init.defaultBranch main`도 함께 설정하면 새 저장소 기본값이 `main`이 된다.
3. VSCode 점검: Extensions에서 `Python` 설치, 좌측 하단 계정 아이콘에서 GitHub 로그인, 필요시 Korean Pack 설치.
4. 이 과제 근거: `실행_가이드.md` 1절의 준비 표와 `요구사항_점검표.md` 5절의 수동 확인 항목이 정확히 이 명령들을 캡처하도록 요구한다.

### 6-3. 파이썬 기초 문법에 대해 설명할 수 있다.

**외울 말:** “변수에 담고, 함수로 나누고, 조건·반복으로 흐름을 만들고, 리스트·딕셔너리에 데이터를 담습니다.”

**자세한 답변:**
1. 변수·함수·모듈: 변수는 값을 담는 이름(`prompts = [...]`). 함수는 입력→처리→출력을 묶은 단위이며 이 과제에서는 “한 함수는 한 역할만” 원칙으로 나눴다(예: 입력은 `get_non_empty_input`, 목록 출력은 `show_prompt_list`). 모듈은 남의 기능을 불러쓰는 것으로 `import copy, json, pathlib, sys, typing` 표준 모듈만 사용하므로 `pip install`이 필요 없다.
2. 조건문·반복문: `if/elif/else`는 메뉴 `1`~`14` 분기(`run_menu_loop`)에 사용. `while True`는 반복 횟수를 모를 때 쓰며 메뉴 전체 반복, 빈값 재입력, 번호 재입력에 사용하고 `14`·`return`으로 탈출한다. `enumerate(리스트, start=1)`로 화면 번호와 값을 함께 꺼낸다.
3. 리스트·딕셔너리: 전체는 순서가 필요해서 `list`, 한 건은 서로 다른 필드를 이름으로 구분해야 해서 `dict`를 썼다 → `list[dict]` 구조. 한 건의 키는 `title/content/category/favorite/view_count` 5개이며 `TypedDict`로 명시했다. `append`로 추가, `pop(위치)`로 삭제, `키 대입`으로 수정한다.
4. 문자열·입력: `input()`은 항상 문자열을 반환하므로 메뉴 키도 `"1"` 문자열로 비교한다. `strip()`으로 앞뒤 공백 제거, `isdigit()+범위 검사`로 번호 유효성 확인, `casefold()`로 대소문자 무시 비교(검색·clos중복), `in`으로 “제목 또는 내용 포함” 부분검색을 구현했다.
5. 복사·파일·예외: `deepcopy`로 기본 데이터를 통째 복사해 실행 간 오염 방지. `json.dump/load(ensure_ascii=False)`로 한글 그대로 저장·복원. `EOFError·KeyboardInterrupt`는 `UserInputCancelled` 하나로 통일해 안전 종료. `if __name__ == "__main__"` 덕분에 `import` 때는 메뉴가 실행되지 않고 테스트가 함수만 빌려쓴다.
6. 이 과제 근거: 위 문법이 모두 `prompt_manager.py`에 들어 있고, `코드_설명.md` 2~10절과 `tests/test_prompt_manager.py` 21개가 각 문법의 동작을 증명한다.

### 6-4. Git이 무엇이고 왜 필요한지 설명할 수 있다.

**외울 말:** “Git은 변경 이력을 남기는 분산 버전 관리 도구이며, 되돌리기·협업·증명을 위해 필요합니다.”

**자세한 답변:**
1. 정의: Git은 파일의 스냅샷을 커밋 단위로 쌓는 분산 버전 관리 시스템이다. 중앙 서버 없이 로컬에도 전체 이력이 있다.
2. 왜 필요한가:
   - 되돌리기: 잘못 고쳐도 이전 커밋으로 복귀 가능(`git log` → `git checkout <커밋>`).
   - 협업: 브랜치로 각자 작업 후 병합, 충돌 지점을 명시적으로 보여줌.
   - 증명·제출: `log --oneline --graph`로 “언제·무엇을·왜” 했는지 제출 근거로 제시. 이 과제의 “의미 있는 커밋 10개 이상” 요구가 바로 이것이다.
   - 실험 안전성: `main`을 안정판으로 두고 기능 브랜치에서 깨뜨려도 본선이 안전.
3. Git vs GitHub: Git은 도구, GitHub는 그 저장소를 올리는 원격 호스팅이다. 로컬 커밋만으로는 백업·공유가 안 되므로 `push`로 GitHub에 올려야 제출이 된다.
4. 이 과제 근거: 기능·테스트·문서·병합 단위로 10개 초과 커밋을 남겼고, `feature/a1-1-prompt-list → main` 병합 커밋 `5aeef4c`가 협업 흐름의 증거다.

### 6-5. init, add, commit, push, pull, checkout, clone, merge가 각각 무엇을 하는지 설명할 수 있다.

**외울 말:** “`init` 시작, `clone` 복사, `add` 후보, `commit` 확정, `push` 올리기, `pull` 받기, `checkout` 이동, `merge` 합치기입니다.”

**자세한 답변:**

| 명령 | 무엇을 하나 | 이 과제 예시 |
| --- | --- | --- |
| `git init` | 현재 폴더를 Git 저장소로 시작(`.git/` 생성). 이미 `clone`한 폴더에서는 불필요 | 처음부터 시작했다면 `git init` 후 `add·commit` |
| `git clone <주소>` | 원격 전체(이력 포함)를 로컬에 복사. 과제 시작점 | `git clone https://github.com/.../codyssey_temporary.git .` |
| `git add <파일>` | 바뀐 파일을 다음 커밋 후보(스테이징)에 올림. 선별 커밋 가능 | `git add "AI 활용 학습 A1-1"` |
| `git commit -m "메시지"` | 후보를 이력 1개로 확정. 메시지에 무엇을·왜를 남김 | `git commit -m "docs(A1-1): expand requirements checklist"` |
| `git push origin main` | 로컬 이력을 원격(`origin`) `main`에 올림. 제출의 마지막 단계 | 매 수정 후 `push` |
| `git pull origin main` | 원격 변경을 받아와 합침. `push` 전·작업 시작 전에 실행해 충돌 예방 | `push` 전 `git pull origin main --rebase` |
| `git checkout -b <브랜치>` / `git checkout <대상>` | 브랜치 생성·전환, 특정 커밋·파일로 이동. 최신 Git은 `switch/restore`로도 가능 | `git checkout -b feature/a1-1-prompt-list` |
| `git merge <브랜치>` | 브랜치를 현재 위치에 합침. fast-forward 또는 병합 커밋 생성 | `main`에서 `git merge feature/a1-1-prompt-list` → `5aeef4c` |

생활 흐름으로 외우면: `clone(최초 1회) → 수정 → add → commit → pull → push` 반복, 기능 단위면 `checkout -b → 작업·commit → checkout main → merge` 추가.

### 6-6. 브랜치를 생성하고 병합할 수 있다.

**외울 말:** “`main`은 안정판으로 두고, 기능은 분리 브랜치에서 완성·테스트 후 병합 커밋으로 합칩니다.”

**자세한 답변:**
1. 생성·전환:
   ```bash
   git checkout -b feature/a1-1-prompt-list
   # 또는 최신 방식: git switch -c feature/a1-1-prompt-list
   ```
2. 작업·확정: 브랜치 안에서 코드 수정 → `add` → `commit` 여러 개. 이 과제에서는 목록 표시(`9a86cb3`) 등을 이 브랜치에서 했다.
3. 본선 복귀·병합:
   ```bash
   git checkout main
   git pull origin main
   git merge feature/a1-1-prompt-list
   git push origin main
   ```
   `merge` 결과로 병합 커밋 `5aeef4c merge(A1-1): integrate prompt list feature`가 남는다. `--no-ff`를 쓰면 fast-forward 상황에서도 병합점이 강제 기록된다.
4. 충돌 시: 같은 위치를 양쪽에서 다르게 고치면 Git이 `<<<<<<<`·`=======`·`>>>>>>>` 표식을 남긴다. 사람이 남길 내용만 남기고 표식을 지운 뒤 저장 → `add` → `commit` → 테스트(`unittest`+`py_compile`) → `push`. 방향을 못 정했으면 `git merge --abort`로 중단.
5. 확인: `git log --oneline --graph --all`에서 분기선과 병합점이 보이면 성공. 제출 캡처도 이 명령이다.
6. 이 과제 근거: 실제 병합 커밋 `5aeef4c`가 저장소에 남아 있으며 `git show 5aeef4c --stat`으로 합친 파일을 확인할 수 있다.

### 6-7. GitHub에 코드를 업로드하고 관리할 수 있다.

**외울 말:** “로컬에서 작게·자주 커밋하고, `push`로 올리고, `.gitignore`로 생성물을 빼고, `pull`로 최신을 유지합니다.”

**자세한 답변:**
1. 업로드手順:
   ```bash
   cd 저장소최상위
   git pull origin main
   git status
   git add "AI 활용 학습 A1-1"
   git commit -m "feat(A1-1): 변경 내용을 한 줄로"
   git push origin main
   ```
   `status`로 의도치 않은 파일이 섞이지 않았는지 먼저 본다. 메시지는 Conventional Commits(`feat·fix·test·docs·refactor·merge`) + 범위(`A1-1`) 형식을 권장한다.
2. 관리:
   - `.gitignore`에 `__pycache__/`, `prompts.json`, `prompts_by_category.md` 같은 생성·개인 파일을 넣어 저장소를 가볍게 유지.
   - VSCode Source Control 패널로도 `add·commit·push·pull·분기 확인` 가능.
   - GitHub 웹에서 커밋 목록·병합점·파일이 보이는지 최종 확인 후 저장소 URL을 제출한다.
3. 막힐 때: `push` 인증 오류 → VSCode GitHub 로그인 확인. `pull` 충돌 → 6-6手順으로 해결 후 다시 `push`. `reset --hard`는 작업이 날아가니 쓰지 않는다.
4. 이 과제 근거: `AI 활용 학습 A1-1/` 폴더가 `main`에 반영되어 있고, 산출 JSON·Markdown은 `.gitignore`로 제외했으며, `README.md`·`실행_가이드.md` 5절에 위 업로드手順이 그대로 적혀 있다.

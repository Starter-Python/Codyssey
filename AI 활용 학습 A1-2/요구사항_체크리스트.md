# 과제 요구사항 체크리스트

이 문서는 제공된 A1-2 과제 안내문을 기준으로, Gemini API 전환 후의 구현 상태를 확인합니다. `구현 완료`는 코드와 문서 반영을 뜻하며, 실제 Gemini 호출은 사용자가 자신의 `GEMINI_API_KEY`를 `.env`에 설정한 환경에서 확인할 수 있습니다.

> **쉽게 읽는 법**: 왼쪽 칸은 "과제에서 요구한 것", 가운데 칸은 "그것이 코드 어디에 있는지(함수 이름)", 오른쪽 칸은 "제대로 되어 있는지"입니다. 함수 이름은 `travel_planner.py` 안의 작은 기능 묶음 이름이라고 생각하면 됩니다.

## 1. 최종 산출물과 CLI

> **원본 요구사항 (2. 최종 결과물 / 4. 기능 요구 사항 - CLI 인터페이스)**
> - CLI 기반 Python 프로그램
> - 입력/요청: `-date "YYYY-MM-DD"` (필수)
> - 출력/화면: 진행 로그 + 결과 저장 경로 안내
> - argparse를 활용하여 CLI로 실행 가능해야 한다. 입력값 검증: 날짜 형식이 올바르지 않으면 사용법을 출력하고 종료한다.
> - README.md: 프로그램 개요, 실행 방법, API 키 설정 방법, 결과물 확인 방법. API 키가 유출되지 않도록 주의 사항 포함

> ⚠️ **구현 메모**: 원문은 `-date`를 필수로 규정했으나, 본 구현은 `-date`를 생략하면 대화형 프롬프트로 날짜를 입력받도록 확장했습니다. 옵션을 주면 원문과 동일하게 동작합니다.

| 요구사항 | 구현 위치 | 상태 |
|---|---|---|
| CLI 기반 Python 프로그램 | `travel_planner.py` | 구현 완료 |
| `-date` 옵션 (생략 시 대화형 입력) | `parse_args()` | 구현 완료 |
| 날짜 형식·실제 날짜 검증 | `datetime.strptime()` + `parser.error()` | 구현 완료 |
| 진행 로그·저장 경로 출력 | `main()` | 구현 완료 |
| 원본 JSON과 최종 Markdown 저장 | `write_results()` | 구현 완료 |
| 실행·보안 안내 README | `README.md` | 구현 완료 |

## 2. API 제공자와 데이터 흐름

> **원본 요구사항 (4. 기능 요구 사항 - API 제공자 선택 규칙 / LLM 연동 / 지도 연동)**
> - LLM API는 아래 중 택1: OpenAI 계열 API / Google Gemini 계열 API → **Google Gemini** 선택
> - 지도/장소 검색 API는 아래 중 택1(국내 장소 검색 가능): Kakao Local / Naver Local Search → **Kakao Local** 선택
> - LLM 입력: 사용자가 입력한 date. 출력: 반드시 JSON으로 파싱 가능한 텍스트. 1차 JSON 최소 스키마: `recommended_city(string)`, `weather(string)`, `events(array of string, 1~3개)`, `reason(string, 2~4문장)`
> - 장소 검색 입력: 1차 JSON의 `recommended_city`(또는 키워드). 출력: 맛집 N곳(권장 5곳). 맛집 아이템 최소 필드: `name`, `address`, `category`, `url`, `x/y 또는 lat/lng`
> - 검색 결과가 0건이면 프로그램이 중단되지 않고 "데이터 없음" 상태로 다음 단계로 진행
> - LLM 최종 리포트 입력: 1차 추천 JSON + 맛집 목록(0건 가능). 출력: Markdown 리포트(추천 지역+이유, 날씨 요약, 행사/축제, 맛집 리스트, 1일 일정 제안, 오류 처리)

| 요구사항 | Gemini 전환 후 구현 | 상태 |
|---|---|---|
| OpenAI 또는 Gemini 계열 LLM | **Google Gemini API** `generateContent` REST API | 구현 완료 |
| 국내 장소 검색 API | Kakao Local 키워드 검색 API | 구현 완료 |
| 1차 추천을 장소 검색 입력으로 연결 | `recommended_city` → `"{city} 맛집"` | 구현 완료 |
| JSON 파싱 가능한 1차 LLM 출력 | Gemini `responseMimeType`과 `responseJsonSchema` 사용 | 구현 완료 |
| 추천 JSON 필수 키 | `recommended_city`, `weather`, `events`, `reason` 검증 | 구현 완료 |
| 맛집 최대 5곳 | Kakao `size=5`, `normalize_place()` | 구현 완료 |
| 맛집 공통 필드 | `name`, `address`, `category`, `url`, `x`, `y` | 구현 완료 |
| 최종 Markdown 리포트 | Gemini 2차 호출 또는 `fallback_report()` | 구현 완료 |

## 3. 오류 처리와 보안

> **원본 요구사항 (4. 기능 요구 사항 - 에러 처리 / API 키 관리(보안) / 결과 저장)**
> - try-except로 API 호출/파싱 오류를 처리한다.
> - API 키 미설정: 즉시 종료 + 설정 방법 안내 출력
> - 지도/장소 API 실패(네트워크/인증/쿼터): 맛집 섹션을 "데이터 없음" 처리하고 리포트 생성은 계속
> - LLM JSON 파싱 실패: 재요청 1회 또는 "필수 키만 다시 JSON으로 출력"하도록 프롬프트를 수정해 재시도 1회
> - 실패 시 결과 리포트에 errors 섹션으로 요약을 남길 수 있도록 내부적으로 오류 목록 관리(빈 리스트여도 무방)
> - API 키를 코드에 직접 작성하지 않는다. 환경변수 또는 .env 파일에서 읽는다. 제출물(README/로그/결과 파일)에 키가 노출되지 않도록 주의
> - results/ 폴더 생성, 실행 날짜 기준 파일 저장. 원본 데이터 JSON에 1차 추천 JSON·맛집 검색 결과·오류 요약(errors: array) 포함. 최종 리포트는 .md로 저장

> ⚠️ **구현 메모**: 원문의 "JSON 파싱 실패 재시도 1회"는 본 구현에서 최대 2회(총 3회 시도)로 완화했고, 무한 재시도는 금지되어 있습니다.

| 요구사항 | 구현 근거 | 상태 |
|---|---|---|
| Gemini 키 미설정 시 즉시 종료 | `build_gemini_settings()` | 구현 완료 |
| Gemini 401/403/429 안내 | `GeminiRequestError`와 `create_recommendation()` | 구현 완료 |
| Gemini JSON 파싱 실패 시 1회 재시도 | 보정 프롬프트를 포함한 2회 반복 | 구현 완료 |
| Kakao 0건·인증·쿼터·네트워크 오류 후 계속 진행 | `search_restaurants()` | 구현 완료 |
| 오류 배열 관리 | `{step, type, message}` 형식의 `errors` | 구현 완료 |
| 키 코드 직접 작성 금지 | `os.getenv()`와 `.env` | 구현 완료 |
| 키의 로그·결과 노출 완화 | `redact_secrets()` | 구현 완료 |

## 5. 보너스 과제 (선택)

> **원본 요구사항 (5. 보너스 과제)**
> - 복수 지역 추천: 1차 추천에서 `recommended_city`를 1개가 아니라 2~3개로 확장(`recommended_cities: [..]`). 각 지역에 대해 맛집 검색, 지역별로 리포트 정리
> - 결과 캐싱(간단 버전): 같은 -date로 재실행할 때 이미 저장된 원본 JSON이 있으면 API 호출을 건너뛰고 리포트를 재생성(또는 그대로 사용)

| 요구사항 | 구현 위치 및 방식 | 상태 |
|---|---|---|
| 복수 지역 추천 (`recommended_cities` 2~3개) | — | 미수행 |
| 결과 캐싱 | `--cached`/`--refresh` 옵션과 `load_cached_data()`로 구현 | 구현 완료 |

> 결과 캐싱(`--cached`/`--refresh`), 입력 정규화(`normalize_city_name`), 불완전 JSON 대응(`extract_json_object`)은 보너스 과제가 아니라 **항목 4 심화 응답 전략**으로 구현·설명합니다.
